# Reed Discover 0.1 — архитектура

## Границы первой версии

Reed Discover — статическое веб-приложение на GitHub Pages. GitHub Actions раз в
три часа забирает публичные материалы, нормализует их и публикует одновременно в
двух представлениях:

```text
MirF Atom → адаптер MirF → нормализованные статьи
                            ├─ feed.xml + items/*.html → RSS / KOReader
                            └─ data/articles.json     → Reed Discover UI

браузер пользователя → localStorage → сохранено / прочитано
                    └→ сборка EPUB на устройстве
```

Сервер, аккаунт и база данных не нужны. GitHub Pages раздаёт одинаковый каталог
всем, а личное состояние никогда не покидает браузер.

## Контракты

- `public/feed.xml` — прежний полнотекстовый RSS 2.0. Его URL, `guid`,
  `content:encoded` и 30 последних записей сохраняются для KOReader.
- `public/items/*.html` — стабильные страницы для чтения и главы EPUB.
- `public/data/articles.json` — версионированный (`version: 1`) каталог карточек.
- `config/sources.json` — реестр источников. Поле `adapter` выбирает обработчик;
  MirF пока использует специальный адаптер, сохраняющий богатую разметку.
- `reed-discover.library.v1` в `localStorage` — только id, время сохранения и
  статус прочтения. Содержимое статьи не дублируется.

`localStorage` выбран вместо IndexedDB, потому что состояние MVP мало, синхронно
и атомарно: несколько сотен записей занимают считанные килобайты. IndexedDB имеет
смысл при офлайн-копиях полных статей, изображениях или синхронизации.

## Reed Me Later внутри Discover

Discover отвечает на вопрос «что почитать», а Reed Me Later — «как сохранить то,
что я уже нашёл». В интерфейсе это одна библиотека: материал из рекомендаций и
произвольная URL получают одинаковые статусы, удаление и общий экспорт.

GitHub Pages хранит произвольную ссылку локально, но не пытается извлечь её полный
текст: браузер обычно не имеет CORS-доступа к сторонним сайтам. Расширенный режим
подключает существующий `reed-me-later` Worker как асинхронный extraction backend:
Readability очищает страницу, GitHub Actions собирает EPUB, а OPDS/Wallabag
доставляют его в KOReader. Таким образом статический MVP остаётся бесплатным и
работает без настройки, а Worker добавляется как необязательная возможность, а
не как условие работы всей ленты.

## Добавление RSS-источника

Следующая итерация выделяет общий модуль `SourceAdapter` с операциями `discover`,
`fetch` и `normalize`. Обычный RSS/Atom проходит универсальный адаптер и
Readability-очистку; сайты с нестандартной разметкой получают небольшой адаптер,
как MirF. Новый источник сначала добавляется выключенным в `config/sources.json`,
прогоняется на тестовых материалах, затем включается.

## Обнаружение источников

Обнаружение не публикует сайты автоматически. Планируемый job обходит исходящие
ссылки из уже одобренных материалов и ищет `<link rel="alternate"` RSS/Atom.
Кандидаты попадают в артефакт `discovered-sources.json` с доменом, URL ленты,
частотой публикаций и числом упоминаний. Владелец репозитория вручную переносит
подходящий кандидат в `config/sources.json`. Это защищает ленту от спама и
неожиданного копирования контента.

## EPUB

EPUB 3 собирается целиком в браузере из выбранных `items/*.html`: создаются
manifest, оглавление и главы, затем минимальный ZIP-контейнер. Файл не отправляется
на сервер и подходит для импорта в KOReader. В 0.1 внешние изображения остаются
ссылками; офлайн-упаковка изображений — отдельное улучшение.

## Миграция и совместимость

Развёртывание идёт в прежний Pages-проект. Подписка KOReader на `feed.xml`
продолжает работать без действий пользователя. Старые `guid` и имена страниц
строятся тем же алгоритмом. Новые файлы только дополняют публикацию. Перед каждым
deploy workflow проверяет оба контракта и не публикует невалидную сборку.
